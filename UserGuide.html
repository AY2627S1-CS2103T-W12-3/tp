CoordiMate User Guide

CoordiMate is a desktop application that helps university CCA EXCO members organise committee information and coordinate their work. It lets users manage contacts and tags, plan events, assign members, and track attendance through a Command Line Interface (CLI) while retaining the benefits of a Graphical User Interface (GUI).

Quick start

  1. Ensure that Java 25 or later is installed on your computer.
    Mac users: Ensure you have the precise JDK version prescribed here.

  2. Download the latest .jar file from here.

  3. Copy the file to the folder you want to use as the home folder for CoordiMate.

  4. Open a terminal, cd to the folder containing the JAR file, and run java -jar coordimate.jar.
    On the first launch, a maximized GUI similar to the one below should appear in a few seconds. Note how the app contains some sample data.

    On subsequent launches, CoordiMate restores whether the window was maximized, together with its most recent non-maximized size and position. If those saved bounds do not fit the current display, such as after disconnecting a secondary screen or changing the display resolution, CoordiMate adjusts the window to remain fully visible.

    The left sidebar switches between Contacts, Events, and Tags and shows commands for the selected view. Click a command name to put only the command word in the input and show its format and an example below the input. Complete the command by typing its arguments after the command word. The main workspace shows a list beside its details, and the command box, feedback, and prefix hints stay at the bottom.

  5. Type a command in the command box and press Enter to execute it. For example, type help and press Enter to open the help window.
    Press Up to recall earlier commands and Down to move toward the command you were typing.
    To browse cards without reaching for the mouse, press Esc to enter Navigation mode, use J/K to move through the active view, S to switch views, then press I to return to Command mode.
    Some example commands you can try:

    • list : Lists all contacts.

    • add n/John Doe p/98765432 e/johnd@example.com r/Member : Adds a contact named John Doe to CoordiMate.

    • delete 3 : Asks to delete the contact with member ID 3. Type y and press Enter to confirm.

    • clear : Deletes all contacts, events, and custom tags.

    • exit : Exits the app.

    In the Contacts view, select a contact from the displayed list to see their phone number, email address, role, birthday, address, organisation, tags, note, and assigned events in the details pane. Contact cards and details, event rosters, and tag member lists show the contact's permanent identifier as ID: <number>. For example, ID: 12 remains ID: 12 when a search makes that contact the first result. Use that same ID in edit, delete, assign, and unassign. Editing or reordering a contact keeps their ID; if a list change hides or removes the selected contact, the details pane clears. Unset optional fields show — (not specified); a contact with no tags shows no tag chips.

  6. Refer to the Features section below for details of each command.

Features

Every command error is followed by the relevant command's description, Parameters:, and Example:. Error messages shown below omit that usage text. Conditions in the error tables assume the rest of the command is valid. If a command has several errors, the first one encountered during validation is reported. Placeholders such as {PREFIX} and {EVENT_NAME} are replaced with the actual parameter prefix, name, member ID, or other details.

Condition Error message
The input is empty or contains only whitespace. Invalid command format.
The command word is unknown or uses the wrong capitalization. Unknown command. Use help to see the available commands. Example: help
Existing data cannot be loaded before a command changes saved data. Saved data could not be loaded. Check the local data file.

For dismiss, data-loading and saving failures instead produce the session-only warning described in Dismissing a reminder.

Notes about the command format:

  • Words in UPPER_CASE are the parameters to be supplied by the user.
    For example, in add n/NAME, replace NAME with a value such as John Doe.

  • Items in square brackets are optional.
    For example, n/NAME [t/TAG] can be used as n/John Doe t/friend or as n/John Doe.

  • Items followed by ... are repeatable and can appear zero or more times.
    For example, [t/TAG]... may be omitted, or written as t/friend or t/friend t/family.

  • Parameters can be in any order.
    For example, if the command specifies n/NAME p/PHONE_NUMBER, p/PHONE_NUMBER n/NAME is also acceptable.

  • Extraneous parameters for commands that take no parameters, such as help, list, exit, and clear, are ignored.
    For example, help 123 is interpreted as help.

  • If you are using a PDF version of this document, be careful when copying and pasting commands that span multiple lines as space characters surrounding line-breaks may be omitted when copied over to the application.

Parameter constraints

The table below lists the values each parameter accepts. Leading and trailing spaces are ignored for every parameter. A command that breaks a constraint is rejected and makes no changes.

Parameter Prefix Constraints
NAME, MEMBER_NAME n/, mem/ 1 to 80 characters. Letters, spaces, hyphens (-), apostrophes ('), and periods (.) only, with at least one letter. Digits are not allowed. Contact names are unique, ignoring case.
PHONE p/ 7 to 15 digits. May start with +, and may contain spaces, hyphens, and brackets. Unique among contacts once spaces, hyphens, and brackets are removed.
EMAIL e/ local-part@domain. The local part uses letters, digits, and _, %, +, -, .; it cannot start or end with a period or contain two periods in a row. The domain is made of labels separated by periods; each label uses letters, digits, and hyphens and cannot start or end with a hyphen. The last label has at least 2 letters. Unique among contacts, ignoring case.
ROLE r/ 1 to 50 characters. Letters, digits, spaces, hyphens, and / only, with at least one letter or digit.
BIRTHDAY b/ A real date in dd-MM-yyyy format that is not in the future, e.g. 18-06-2004.
LEAVE_END_DATE lv/ A real date in dd-MM-yyyy format that is not in the past, e.g. 30-11-2026. Today's date is allowed.
ADDRESS a/ 1 to 200 characters. Any printable characters.
ORGANISATION o/ 1 to 80 characters. Letters, digits, spaces, hyphens, and & only, with at least one letter or digit.
NOTE m/ 1 to 500 characters. Any printable characters.
TAG, NEW_TAG t/, at/, rt/ 1 to 30 characters. English letters and digits only, with no spaces. Tags are unique, ignoring case.
EVENT_NAME, NEW_EVENT_NAME evn/, nevn/ At least one non-space character. Any characters are allowed, subject to the note below. Event names are unique, ignoring case.
START_TIME, END_TIME st/, et/ A real date in dd-MM-yyyy format, optionally followed by a 24-hour time in HH:mm format, e.g. 17-09-2026 or 17-09-2026 16:30. The start must not be after the end.
STATUS att/ present or absent, ignoring case.
MEMBER_ID c/ for assign and unassign; none for edit and delete A permanent positive integer from 1 to 2147483647 identifying a saved contact, independent of the displayed list.
KEYWORD none At least one non-space character.

Note: In commands that accept multiple prefixed parameters, such as add and addevent, text within a value that looks like another parameter—a space followed by letters and /—is read as the start of another parameter. For example, addevent evn/Planning tag/review ... is rejected with an unknown-parameter error, and in m/Check a/v setup the text after a/ is read as the address. Write such text without the space before it, or without the /, e.g. m/Check AV setup.

Commands parse their arguments differently. For example, search treats the entire remainder as its keyword, while tag commands tokenize only their recognised t/ prefix.

Navigating cards with the keyboard

CoordiMate starts in Command mode, with the command box ready for input. The mode indicator below the command box shows the current mode and its available shortcuts.

Use the following keys to browse Contacts, Events, or Tags without the mouse:

Key Result
Esc Enter Navigation mode from Command mode.
J Select the next card in the active view. If nothing is selected, select the first card.
K Select the previous card in the active view. If nothing is selected, select the last card.
S Switch to the next view, wrapping from Tags back to Contacts.
I Return to Command mode and focus the command box.

Navigation stops at the first or last card rather than wrapping around. On an empty list, J and K do nothing. The shortcuts apply to whichever of the Contacts, Events, or Tags views is active. Each view keeps its selection when you switch away and back.

Other unmodified keys, including Enter, Space, Tab, and the arrow keys, are disabled in Navigation mode. Pressing Esc moves keyboard focus away from controls such as a reminder's Dismiss button, so those controls cannot be activated accidentally. Mouse controls remain available.

You can chain navigation and command entry without clicking. For example, press Esc, J, J, I, then type a command. Any unfinished command remains in the command box while you navigate.

Clicking the command box or choosing a command from the left sidebar enters Command mode. Clicking the contact, event, or tag list enters Navigation mode. Mode switching is disabled while CoordiMate is waiting for confirmation of a delete command, so your confirmation input is not intercepted.

Reusing commands with command history

With the command box focused, press Up to recall the most recently entered command. Keep pressing Up to move through older commands, or press Down to move forward. Moving past the newest command restores any unfinished text that was in the box before you started browsing. You can edit a recalled command; it runs only when you press Enter or select Enter.

History includes commands that produced errors, so you can correct and retry them. There is no fixed maximum number of entries; the practical limit is the memory available to the app. History clears when you close CoordiMate. Blank inputs and responses to a delete confirmation are not stored. History navigation is paused while CoordiMate is waiting for a delete confirmation.

Viewing help: help

Opens a resizable Help window containing a keyboard-navigation summary and a scrollable two-column table of every available command and its usage format. The User Guide website and Copy URL button remain at the bottom of the window for access to detailed instructions. Select Close or press Esc to dismiss the Help window without exiting CoordiMate. Selecting Help in the top bar opens this window directly. Press Fn + F1 to open it with the keyboard. In the command formats, parameters enclosed in square brackets [ ] are optional.

Format: help

Adding a contact: add

Adds a contact to CoordiMate.

Contact names must be unique after trimming surrounding spaces and ignoring case. An add is also rejected if its phone number or email address is already used by another contact. Phone numbers are compared without spaces, hyphens, or brackets; email addresses are compared without regard to case. For any duplicate, CoordiMate reports A contact with this name, phone number, or email already exists. and makes no changes. If the local contact data cannot be loaded or saved, CoordiMate reports an error and leaves the contact list unchanged.

Format: add n/NAME p/PHONE e/EMAIL r/ROLE [b/BIRTHDAY] [a/ADDRESS] [o/ORGANISATION] [lv/LEAVE_END_DATE] [t/TAG]... [m/NOTE]

Name, phone, email, and role are required. Each field accepts the following values; surrounding spaces are ignored:

Adding an event: addevent

Creates an event and saves it to the local data file.

Format: addevent evn/EVENT_NAME st/START_TIME et/END_TIME

Each parameter must appear once. Leading and trailing whitespace is removed before an event name is checked. The resulting name must contain 1 to 100 printable characters; line breaks and other control characters within the name are rejected. Names must be unique, ignoring case. An overlong name reports Event name must not exceed 100 characters. Example: evn/Final Concert. An invalid character reports Invalid event name. Use letters, digits, spaces, or punctuation. Example: evn/Final-Concert. Different events may share the same start and end times.

Start and end times use dd-MM-yyyy, optionally followed by HH:mm in 24-hour format. Date-only values are saved without a time of day.

The start must not be after the end. Equal start and end values are allowed. Dates are compared first. On the same date, times are compared only when both are specified.

Examples:

  • addevent evn/Final Concert st/08-08-2026 15:00 et/08-08-2026 18:00
  • addevent evn/Student Life Fair st/09-10-2026 et/10-10-2026

Success: Created Event Student Life Fair. Start Time: 09-10-2026. End Time: 10-10-2026.

Use the Events tab on the left to browse saved events. Selecting an event shows its start time, end time, duration, and members. Each member row shows the contact's role, organisation, tags, notes, and attendance status. A successful addevent opens this tab and selects the new event. Each event card shows its member count and attendance summary. At narrower window sizes, the list appears above the details. The list and details divider can be dragged, but the details pane keeps a minimum width while the panes are side by side.

Command feedback appears above the input at the bottom of the window. Rejected commands show a red feedback band and input border. The command stays in the input so you can correct it, then press Enter or click Retry.

Condition Error message
An event with the same name already exists, ignoring case. An event with this name already exists. No changes were made.
The event name is empty. Event name must not be empty. Example: evn/Final Concert
All required parameters are present, but st/ contains only whitespace. Start time must not be empty. Example: st/17-09-2026 16:30
All required parameters are present, but et/ contains only whitespace. End time must not be empty. Example: et/17-09-2026 18:30
A time is invalid or incorrectly formatted. Invalid event time. Use dd-MM-yyyy with an optional time in HH:mm format. Example: st/17-09-2026 16:30
The start is after the end. Start time must not be after end time. Example: st/17-09-2026 16:30 et/17-09-2026 18:30
Any required parameter (evn/, st/, or et/) is missing, or there is text before the first parameter. Invalid command format.
A parameter is repeated. Parameter {PREFIX} may only be specified once.
An unknown parameter is used. Unknown parameter: {PREFIX}.

Editing an event: editevent

Edits the name, start time, and/or end time of an existing event and saves the changes.

Format: editevent evn/EVENT_NAME [nevn/NEW_EVENT_NAME] [st/NEW_START_TIME] [et/NEW_END_TIME]

EVENT_NAME must match the saved name, ignoring case. Leading and trailing whitespace is removed. Lookup capitalization does not change the saved display name; nevn/ sets the new display name using the supplied capitalization. Provide at least one field to edit; omitted fields keep their existing values. Each parameter may appear only once.

The new name follows the same rules as in addevent: 1 to 100 printable characters, not duplicating another event's name, ignoring case. Start and end times use dd-MM-yyyy [HH:mm]; a date is required and a 24-hour time is optional. The updated start must not be after the updated end, using the same ordering rules as addevent.

Examples:

  • editevent evn/Final Concert st/08-08-2026 16:00 et/08-08-2026 19:00
  • editevent evn/Student Life Fair nevn/NUS Student Life Fair et/10-10-2026
  • editevent evn/CCA MEETING nevn/CCA MEETING changes the display name of CCA Meeting to CCA MEETING.

Success: Edited Event NUS Student Life Fair. Start Time: 09-10-2026. End Time: 10-10-2026.

Automatic event reminders

CoordiMate shows reminders in the Upcoming events panel below the menu bar and above the workspace. The panel appears when reminders are available and stays visible across the Contacts, Events, and Tags views. It hides when no reminders remain. No command is needed to receive reminders, which appear only while CoordiMate is running.

CoordiMate checks saved events on startup and once per minute while the window is open. It also refreshes reminders after commands, including event edits and deletions. A reminder becoming eligible or expiring as time passes updates at the next periodic check.

Reminder timing follows your computer's local time zone:

  • For a start with a time of day, the reminder becomes eligible exactly 24 hours before the start. It remains eligible at the exact start time. Once the start has passed, the next check removes it, even if the event has not ended.
  • For a start with only a date, the reminder is eligible throughout the preceding calendar day and the event's start date. For example, a start of 20-10-2026 qualifies from midnight at the beginning of 19-10-2026 until midnight at the beginning of 21-10-2026, excluding that final midnight.

Each reminder displays its index and the saved event name, start, and end. For example:

1. Upcoming event: Final Concert
Starts: 20-10-2026 15:00
Ends: 20-10-2026 18:00

This timed event qualifies from 19-10-2026 15:00 through 20-10-2026 15:00, including both boundaries. Several reminders appear in ascending order of start time, with ties ordered by name, ignoring case. For ordering, a date-only start counts as the beginning of its date; the reminder still displays the saved date without adding a time. Each event has at most one active reminder. Indexes start at 1 and follow this order. They update whenever the reminder list changes.

Click Dismiss beside a reminder or use dismiss INDEX to hide it. CoordiMate saves the dismissal immediately, so it stays dismissed after restarting. Renaming the event, editing only its end, or supplying the same start value keeps the dismissal. Changing its start date or time resets the dismissal, including when switching between a timed and date-only start or reverting to a previously dismissed start. The revised reminder appears if its new start qualifies under the timing rules above. Rejected or unsaved edits leave reminders unchanged.

Deleting an event removes its reminder. The clear command removes all events and their reminders. Deleting and then recreating an event creates a new reminder if its start qualifies, even when the name and schedule match the deleted event.

If CoordiMate cannot save a dismissal, it hides the reminder for the current session and shows Reminder dismissal could not be saved and may reappear after restarting. with a Not saved status in the feedback area above the command input. The dismissal has not been saved, so the reminder may return after restarting.

If the saved data file is invalid, CoordiMate starts with an empty dataset and shows no event reminders. See Editing the data file for details of data-loading errors.

Dismissing a reminder: dismiss

Dismisses one reminder using its current index in the Upcoming events panel and saves the dismissal. The event, its members, and its attendance records remain available. The current tab and contact filter stay selected.

Format: dismiss INDEX

  • INDEX is required and must be a positive integer starting at 1.
  • Use the index shown beside the reminder in the Upcoming events panel. The contact and event lists have their own ordering.
  • Remaining reminders are renumbered after dismissal. Use their current indexes for subsequent commands.

Examples:

  • dismiss 1 dismisses the first reminder in the panel.
  • dismiss 2 dismisses the second reminder, if at least two reminders are shown.

Success: Reminder dismissed: {EVENT_NAME}. The reminder disappears immediately and stays dismissed after restarting. Changing the event's start resets its dismissal as described in Automatic event reminders.

Condition Error message
The index is missing. Invalid command format.
The index is zero, negative, non-integer, greater than 2147483647, or followed by extra arguments. Index must be a positive integer. Example: 1
No reminder has that index, including when the panel is empty. No reminder exists at index {INDEX}. Use an index from the Upcoming events panel.
The reminder at that index is no longer upcoming (for example, its event has started) because the panel had not yet updated. Reminder {INDEX} is no longer upcoming, so it was not dismissed. Check the updated Upcoming events panel.

Invalid input dismisses no reminder. If loading or saving the data file fails, the reminder is hidden for the current session and feedback shows Reminder dismissal could not be saved and may reappear after restarting. with a Not saved status. The saved dismissal history remains unchanged, so the reminder may return after restarting. This is the same behavior as the Dismiss button.

Assigning members to an event: assign

Assigns one or more contacts to an existing event as members and saves the change.

Format: assign evn/EVENT_NAME c/MEMBER_ID [MORE_MEMBER_IDS]...

  • EVENT_NAME must match a saved event name, ignoring case. Leading and trailing whitespace is removed.
  • MEMBER_ID is a contact's permanent numeric ID, from 1 to 2147483647. Separate several IDs with spaces. IDs resolve across all saved contacts, including those hidden by searches, filters, or an empty results list.
  • Each parameter may appear only once.
  • All IDs are checked before any change is made. If any ID is invalid or does not exist, no contacts are assigned.
  • Contacts who are already assigned to the event are skipped, and an ID repeated in the same command is counted once.
  • New members are added after the existing members, in the order given.

Selecting the event in the Events tab shows its members under Members.

Examples:

  • assign evn/Final Concert c/2 assigns the contact with member ID 2 to Final Concert.
  • assign evn/student life fair c/1 4 5 assigns the contacts with member IDs 1, 4, and 5 to Student Life Fair.
  • If Bernice has member ID 12, search Bernice followed by assign evn/Final Concert c/12 assigns Bernice regardless of her position in the results.

Success: Assigned 2 member(s) to Final Concert.

Saving the data

Saved member IDs stay tied to the same contacts across restarts. Older files receive unique IDs for contacts that lack them when loaded; the next successful save records those IDs.

IDs are assigned automatically and cannot be changed through commands. Deleting a contact leaves a gap; adding another contact does not reuse the deleted ID. Editing contacts, searching, filtering, and changing list order keep existing IDs. The clear command starts an empty dataset, with IDs starting from 1 again.

CoordiMate automatically saves data after commands that change it. You do not need to save manually.

A command that changes your data is saved to the data file before the change appears in the app. If the data cannot be saved, the command is rejected with an error such as Event could not be saved. No changes were made. and both the app and the data file stay as they were, so what you see always matches what is saved.

Commands that do not change saved data also attempt to save after running. A save failure reports one of the following messages; a command may already have changed the displayed view when this happens.

Condition Error message
Saving is denied by file permissions. Data could not be saved to {DETAILS}. Check write permissions for the file and its folder.
Another file error prevents saving. Data could not be saved. Check the local data file. Details: {DETAILS}

{DETAILS} is supplied by the operating system and can include a file path or an explanation of the failure.

Editing the data file

CoordiMate data is saved automatically as a JSON file [JAR file location]/data/coordimate.json. Advanced users are welcome to update data directly by editing that data file.

Caution: If your changes make the data file invalid, CoordiMate starts with an empty dataset at the next run. While the file is invalid, commands that change data (such as add, addevent, and clear) are rejected with Saved data could not be loaded. Check the local data file. and leave the file untouched, so that you can close the app and fix it. Commands such as list, search, and filter save the data currently in the app, which replaces the invalid file. We therefore recommend backing up the file before editing it.
Each name in an event's members list must exactly match the name of a saved contact, or the data file is invalid.
Each contact's memberId must be a unique integer from 1 to 2147483647. Keep existing IDs unchanged. Keep the top-level nextMemberId field: it must exceed every saved ID, must not be reduced after deleting contacts, and cannot exceed 2147483648.
If a contact uses a tag that is missing from the top-level tags list, CoordiMate adds it to the global tag list when the file is loaded. Existing top-level tags, including unused tags, retain their saved order and capitalization.
Furthermore, certain edits can cause CoordiMate to behave in unexpected ways (e.g., if a value entered is outside of the acceptable range). Therefore, edit the data file only if you are confident that you can update it correctly.

FAQ

Q: How do I transfer my data to another computer?
A: Install the app on the other computer and overwrite the data file it creates with the data file from your previous CoordiMate home folder.

Known issues

  1. If you minimize the Help Window and then run the help command (or use the Help menu, or press Fn + F1) again, the original Help Window will remain minimized, and no new Help Window will appear. The remedy is to manually restore the minimized Help Window.
