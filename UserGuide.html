CoordiMate User Guide

CoordiMate is a desktop application that helps university CCA EXCO members organise committee information and coordinate their work. It lets users manage contacts and tags, plan events, assign members, and track attendance through a Command Line Interface (CLI) while retaining the benefits of a Graphical User Interface (GUI).

Quick start

  1. Ensure that Java 25 or later is installed on your computer.
    Mac users: Ensure you have the precise JDK version prescribed here.

  2. Download the latest .jar file from here.

  3. Copy the file to the folder you want to use as the home folder for CoordiMate.

  4. Open a terminal, cd to the folder containing the JAR file, and run java -jar coordimate.jar.
    On the first launch, a maximized GUI similar to the one below should appear in a few seconds, together with a short tutorial. Note how the app contains some sample data.

  5. Type a command in the command box and press Enter to execute it. For example, type help and press Enter to open the help window.
    Some example commands you can try:

    • list : Lists all contacts and events.

    • add n/John Doe p/98765432 e/johnd@example.com r/Member : Adds a contact named John Doe to CoordiMate.

    • delete 3 : Asks to delete the contact with member ID 3. Type y and press Enter to confirm.

    • clear : Deletes all contacts, events, and custom tags, and restores the default tags.

    • exit : Exits the app.

  6. Read The main window for a tour of the screen, and Features for details of each command.

The main window

  • Top bar: File > Exit closes CoordiMate. Help (Fn + F1) opens the help window, and Tutorial (Fn + F2) restarts the tutorial.

  • Upcoming events panel: appears below the top bar when an event is about to start. See Automatic event reminders.

  • Sidebar: switches between the Contacts, Events, and Tags views, and shows how many items each has. Below the views, it lists the commands for the selected view. Click a command name to put the command word in the command box and show its format and an example below the box, then type its arguments.

  • List and details: each view shows a list beside the details of the selected item.

    • Contacts: the details show the contact's phone number, email address, role, birthday, address, organisation, tags, note, leave, and assigned events. Unset optional fields show — (not specified). If a list change hides or removes the selected contact, the details pane clears.
    • Events: each event card shows its member count and attendance summary. The details show the start time, end time, duration, and members. Each member row shows the contact's role, organisation, tags, notes, current leave status, and attendance status.
    • Tags: the details show the contacts that have the selected tag. See Viewing all tags.

    At narrower window sizes, the list appears above the details. The divider between them can be dragged, but the details pane keeps a minimum width while the panes are side by side.

  • Command box and feedback: type a command and press Enter, or click Enter. The result appears in the feedback area above the box; scroll it to read a long message. A rejected command shows a red feedback band and input border, and stays in the box so you can correct it, then press Enter or click Retry. Below the box, CoordiMate shows the current keyboard mode and the prefixes you can use.

  • Bottom bar: shows where your data file is saved.

Member IDs: contact cards and details, event rosters, and tag member lists show each contact's permanent identifier as ID: <number>. Use that ID in edit, delete, archive, unarchive, assign, and unassign. It does not change when you edit the contact or when a search or filter reorders the list, so ID: 12 stays ID: 12 even when a search makes that contact the first result.

Which view opens after a command: contact commands open Contacts, event commands open Events, and tag commands open Tags. assign and unassign keep the current view and refresh its details. A failed command keeps the current view. Successful add and edit commands select and reveal the affected contact. After a confirmed deletion, the contact now at the removed contact's position is selected, or the previous contact if the removed contact was last.

Window size and position: CoordiMate remembers whether the window was maximized, and its last size and position. If those no longer fit your display, for example after disconnecting a second screen, it adjusts the window to stay fully visible. On displays large enough, the minimum window size is 1200 × 800. On smaller displays, CoordiMate fits the available screen.

Features

Every command error is followed by the relevant command's description, Parameters:, and Example:. Error messages shown below omit that usage text. Conditions in the error tables assume the rest of the command is valid. If a command has several errors, the first one encountered during validation is reported. Placeholders such as {PREFIX} and {EVENT_NAME} are replaced with the actual parameter prefix, name, member ID, or other details.

Condition Error message
The input is empty or contains only whitespace. Invalid command format.
The command word is unknown or uses the wrong capitalization. Unknown command. Use help to see the available commands. Example: help
Existing data cannot be loaded before a command changes saved data. Saved data could not be loaded. Check the local data file.

For dismiss, data-loading and saving failures instead produce the session-only warning described in Dismissing a reminder.

Notes about the command format:

  • Words in UPPER_CASE are the parameters to be supplied by the user.
    For example, in add n/NAME, replace NAME with a value such as John Doe.

  • Items in square brackets are optional.
    For example, n/NAME [t/TAG] can be used as n/John Doe t/friend or as n/John Doe.

  • Items followed by ... are repeatable and can appear zero or more times.
    For example, [t/TAG]... may be omitted, or written as t/friend or t/friend t/family.

  • Parameters can be in any order.
    For example, if the command specifies n/NAME p/PHONE_NUMBER, p/PHONE_NUMBER n/NAME is also acceptable.

  • Commands that take no parameters, such as help, tutorial, exit, and clear, reject extraneous parameters.
    For example, help 123 is invalid; use help instead.

  • If you are using a PDF version of this document, be careful when copying and pasting commands that span multiple lines as space characters surrounding line-breaks may be omitted when copied over to the application.

Parameter constraints

The table below lists the values each parameter accepts. Leading and trailing spaces are ignored for every parameter. In contact names and event names, several spaces in a row are saved as one space, so Alex Yeoh is saved and matched as Alex Yeoh. Contact names accept only ordinary spaces internally. Event names also accept Unicode space separators, including em, thin, ideographic, and non-breaking spaces; these are saved and matched as ordinary spaces. A command that breaks a constraint is rejected and makes no changes.

Parameter Prefix Constraints
NAME, MEMBER_NAME n/, mem/ 1 to 80 characters. Letters, spaces, hyphens (-), apostrophes ('), and periods (.) only, with at least one letter. The words s/o and d/o (any capitalization) are also allowed, e.g. Rajesh s/o Kumar. Digits are not allowed. Several spaces in a row count as one. Contact names are unique, ignoring case and extra spaces.
PHONE p/ 7 to 15 digits. May start with + or a bracketed country code such as (+65), and may contain spaces, hyphens, and brackets. Brackets must come in pairs that each enclose at least one digit, and cannot be nested. Unique among contacts once spaces, hyphens, and brackets are removed.
EMAIL e/ local-part@domain, at most 254 characters, with a local part of at most 64 characters. The local part uses letters, digits, and _, %, +, -, .; it cannot start or end with a period or contain two periods in a row. The domain is made of labels separated by periods; each label uses letters, digits, and hyphens and cannot start or end with a hyphen. The last label has at least 2 letters. Unique among contacts, ignoring case.
ROLE r/ 1 to 50 characters. Letters, digits, spaces, hyphens, and / only, with at least one letter or digit.
BIRTHDAY b/ A real date in dd-MM-yyyy format that is not in the future, e.g. 18-06-2004.
LEAVE_END_DATE lv/ A real date in dd-MM-yyyy format that is not in the past, e.g. 30-11-2026. Today's date is allowed.
ADDRESS a/ 1 to 200 printable characters, including at least one visible character.
ORGANISATION o/ 1 to 80 characters. Letters, digits, spaces, and - & . , ' ( ) / only, with at least one letter or digit. Several spaces in a row count as one.
NOTE m/ 1 to 500 printable characters, including at least one visible character.
TAG, NEW_TAG t/, at/, rt/ 1 to 30 characters. English letters and digits only, with no spaces. Tags are unique, ignoring case. A contact can have at most 15 tags.
EVENT_NAME, NEW_EVENT_NAME evn/, nevn/ 1 to 100 printable Unicode characters, including at least one visible character. Internal tabs, line breaks, and control characters are rejected. Several spaces in a row count as one. Event names are unique, ignoring case and extra spaces. See the parameter syntax note below.
START_TIME, END_TIME st/, et/ A real date in dd-MM-yyyy format, optionally followed by a 24-hour time in HH:mm format, e.g. 17-09-2026 or 17-09-2026 16:30. The start must not be after the end.
STATUS att/ present or absent, ignoring case.
MEMBER_ID c/ for assign and unassign; none for edit, delete, archive, and unarchive A permanent positive integer from 1 to 2147483647 identifying a saved contact, independent of the displayed list.
KEYWORD none At least one non-space character.

"Printable" excludes line breaks and other control characters. "Visible" excludes spaces, zero-width and formatting characters, accent marks on their own, and blank filler characters such as U+3164 Hangul Filler.

Note: In commands that accept multiple prefixed parameters, such as add and addevent, text within a value that looks like another parameter—a space followed by letters and /—is read as the start of another parameter. Unicode whitespace, including em and non-breaking spaces, uses the same parameter boundaries as ordinary spaces. It cannot be used to hide a parameter inside an event name. For example, addevent evn/Planning tag/review ... is rejected with an unknown-parameter error, and in m/Check a/v setup the text after a/ is read as the address. Write such text without the space before it, or without the /, e.g. m/Check AV setup. The exception is s/o and d/o followed by a space or the end of the input, which are read as part of a name, e.g. n/Rajesh s/o Kumar.

Commands parse their arguments differently. For example, search treats the entire remainder as its keyword, while tag commands tokenize only their recognised t/ prefix.

When a command fails

A command that fails makes no changes. Failures take two shapes:

  • An invalid field value: the error message names the field, restates its rule, and gives an example — see Parameter constraints for the full rules.
  • A command-format error, such as a missing, unknown, or duplicated parameter: run help or check the command's Format: line.

Each command section below lists only the errors you couldn't work out from these two rules or from Parameter constraints — for example, a saved value that conflicts with another contact, or an identifier that matches more than one saved contact.

General commands

Viewing help: help

Opens a resizable Help window containing a keyboard-navigation summary and a scrollable two-column table of every available command and its usage format. The User Guide website and Copy URL button remain at the bottom of the window for access to detailed instructions. Select Close or press Esc to dismiss the Help window without exiting CoordiMate. Selecting Help in the top bar opens this window directly. Press Fn + F1 to open it with the keyboard. In the command formats, parameters enclosed in square brackets [ ] are optional.

Format: help

Taking the tutorial: tutorial

The first time CoordiMate starts, a guided overlay opens automatically. Use ← Back and Next → or press the Left and Right Arrow keys to move through the sixteen steps. Press Tab or Shift + Tab to move between the tutorial's buttons. Select Close (Esc) or press Esc to leave the tutorial. On the last step, Finish → or the Right Arrow key completes it. The tour introduces the Contacts, Events, and Tags views; their lists and details; the command box; keyboard navigation; and Help. It selects each view as it is introduced and leaves the current view selected when you close it. The highlighted area stays bright while the rest of the app is dimmed. The app cannot be used to enter commands during the tour.

To take the tutorial again, enter tutorial, select Tutorial beside Help in the top bar, or press Fn + F2. The tutorial always starts again from its first step.

Format: tutorial

Listing contacts and events: list

Shows all active contacts and events, removing any search, filter, or members view. list archived instead shows only archived contacts and events.

Format: list [archived]

  • list shows the contacts and events that are not archived. This is the normal view.
  • list archived shows only archived contacts in the Contacts tab and only archived events in the Events tab. The tabs and the event list heading read Archived contacts and Archived events while this view is open, and an empty list shows No archived contacts. or No archived events. archived may be written in any capitalization.
  • Both forms open the Contacts tab.
  • In the archived view, the left sidebar lists only unarchive (or unarchiveevent in the Events tab) and list. Other commands still work: search, filter, and members look only at archived contacts, and edit, delete, editevent, deleteevent, and markattendance work on archived items. Unarchived items leave the view immediately.
  • add and addevent return to the normal view, so that the new contact or event is visible. Opening the tutorial also returns to the normal view, since it walks through the normal lists and commands.

Examples:

  • list returns to the normal view.
  • list archived shows the archived contacts and their member IDs. unarchive 12 then restores the contact with member ID 12.

Success: Listed all contacts. or Listed archived contacts and events. Use list to return to active contacts and events.

Condition Error message
Anything other than archived follows list. Unknown list option: {OPTION}. Use list, or list archived to show archived contacts and events.

Clearing all entries: clear

Deletes all contacts, events, and custom tags from CoordiMate. The default tags (EXCO, Sponsor, UniversityStaff, and Logistics) are restored, including any that were renamed or deleted.

Format: clear

Success: CoordiMate has been cleared!

Caution: clear takes effect immediately, without asking for confirmation, and cannot be undone.

The cleared data is saved before the contact, event, and tag lists change. If the local data file cannot be read, CoordiMate reports Saved data could not be loaded. Check the local data file. If saving fails, it reports CoordiMate could not be cleared. No changes were made. In either case, the displayed data remains unchanged.

Exiting the program: exit

Closes CoordiMate. Your data is already saved, so nothing is lost.

Format: exit

Navigating cards with the keyboard

CoordiMate starts in Command mode, with the command box ready for input. The mode indicator below the command box shows the current mode and its available shortcuts.

The mode indicator below the command box, showing Navigation mode and its shortcuts.

Use the following keys to browse Contacts, Events, or Tags without the mouse:

Key Result
Esc Enter Navigation mode from Command mode.
J Select the next card in the active view. If nothing is selected, select the first card.
K Select the previous card in the active view. If nothing is selected, select the last card.
S Switch to the next view, wrapping from Tags back to Contacts.
I Return to Command mode and focus the command box.

Navigation stops at the first or last card rather than wrapping around. On an empty list, J and K do nothing. The shortcuts apply to whichever of the Contacts, Events, or Tags views is active. Each view keeps its selection when you switch away and back.

Other unmodified keys, including Enter, Space, Tab, and the arrow keys, are disabled in Navigation mode. Pressing Esc moves keyboard focus away from controls such as a reminder's Dismiss button, so those controls cannot be activated accidentally. Mouse controls remain available.

You can chain navigation and command entry without clicking. For example, press Esc, J, J, I, then type a command. Any unfinished command remains in the command box while you navigate.

Clicking the command box or choosing a command from the left sidebar enters Command mode. Clicking the contact, event, or tag list enters Navigation mode. Mode switching is disabled while CoordiMate is waiting for confirmation of a delete command, so your confirmation input is not intercepted.

Reusing commands with command history

With the command box focused, press Up to recall the most recently entered command. Keep pressing Up to move through older commands, or press Down to move forward. Moving past the newest command restores any unfinished text that was in the box before you started browsing. You can edit a recalled command; it runs only when you press Enter or select Enter.

History includes commands that produced errors, so you can correct and retry them. There is no fixed maximum number of entries; the practical limit is the memory available to the app. History clears when you close CoordiMate. Blank inputs and responses to a delete confirmation are not stored. History navigation is paused while CoordiMate is waiting for a delete confirmation.

Managing contacts

Adding a contact: add

Adds a contact to CoordiMate.

Contact names must be unique, ignoring case and extra spaces. Surrounding spaces are removed and several spaces in a row are saved as one, so n/Alex Yeoh is saved as Alex Yeoh and is a duplicate of an existing Alex Yeoh. An add is also rejected if its phone number or email address is already used by another contact. Phone numbers are compared without spaces, hyphens, or brackets; email addresses are compared without regard to case. For any duplicate, CoordiMate reports A contact with this name, phone number, or email already exists. and makes no changes. If the local contact data cannot be loaded or saved, CoordiMate reports an error and leaves the contact list unchanged.

Format: add n/NAME p/PHONE e/EMAIL r/ROLE [b/BIRTHDAY] [a/ADDRESS] [o/ORGANISATION] [lv/LEAVE_END_DATE] [t/TAG]... [m/NOTE]

  • Name, phone, email, and role are required; birthday, address, organisation, leave end date, and note are optional. Surrounding spaces are ignored. Each field follows the constraints in Parameter constraints.
  • A value that breaks a constraint is rejected with a message stating that field's constraint, such as Invalid organisation. Use 1 to 80 characters: letters, digits, spaces, and - & . , ' ( ) /, with at least one letter or digit. Example: o/NUS Student Affairs.
  • An empty b/, a/, o/, lv/, or m/ leaves that field unset, as does omitting it.
  • Non-tag fields may appear only once; t/TAG may repeat. An empty t/ clears the tags collected so far.
  • A tag that matches a saved tag, ignoring capitalization, uses the saved tag's capitalization; for example, t/exco gives the contact the default EXCO tag. A valid new tag keeps its typed capitalization and is saved as a custom tag.
  • Successful feedback is Contact saved successfully: NAME. After a successful add, CoordiMate selects and reveals the new contact so its details are shown. Unset optional values are shown as — (not specified) in the details pane, but remain unset in storage.

Tip: A contact can have up to 15 tags, including zero. Tags that differ only in capitalization count as one. Parameters can be supplied in any order.

Aisha Tan's contact card and details pane, shown automatically after add saves her.

Examples:

  • add n/Aisha Tan p/+6591234567 e/aisha@example.com r/Logistics t/EXCO m/Handles venue bookings
  • add n/Mr Lim p/90801110 e/lim@example.com o/NUS Student Affairs r/University Staff t/UniversityStaff
  • add n/Rajesh s/o Kumar p/90000001 e/rajesh@example.com r/Member adds a contact whose name includes s/o.
  • add n/Ben Ong p/91112222 e/ben@example.com r/Publicity lv/30-11-2026 adds a contact who is on leave until 30 November 2026. See Marking a contact as on leave.
Condition Error message
Another contact has the same name, phone number, or email. A contact with this name, phone number, or email already exists.

If saving fails, the command reports Contact could not be saved. No changes were made.

Editing a contact: edit

Edits an existing contact in CoordiMate.

Format: edit MEMBER_ID [n/NAME] [p/PHONE] [e/EMAIL] [r/ROLE] [b/BIRTHDAY] [a/ADDRESS] [o/ORGANISATION] [m/NOTE] [lv/LEAVE_END_DATE] [t/TAG]... [at/TAG]... [rt/TAG]...

Or: edit target/IDENTIFIER [n/NAME] [p/PHONE] [e/EMAIL] [r/ROLE] [b/BIRTHDAY] [a/ADDRESS] [o/ORGANISATION] [m/NOTE] [lv/LEAVE_END_DATE] [t/TAG]... [at/TAG]... [rt/TAG]...

  • Edits the contact with the specified permanent MEMBER_ID, including contacts hidden by a search or filter. For example, edit 12 r/President always targets member ID 12, even when that contact is the first search result.
  • Alternatively, target/IDENTIFIER finds an exact saved name, phone number, or email address across all contacts, including those hidden by the current search or filter. Names ignore letter case and extra spaces, emails ignore letter case; phone numbers ignore spaces, hyphens, and brackets. Supply either a member ID or target/, not both.
  • If several contacts match an identifier, the command lists each match's member ID, name, phone, and email, including hidden matches. Retry with a member ID, unique phone number, or email address.
  • If no contact matches target/, or the member ID does not exist, the command reports an error without changing any contact.
  • Provide at least one field or tag operation. Omitted fields retain their existing values.
  • Name, phone, email, and role cannot be cleared. Use b/, a/, o/, lv/, or m/ with no value to clear that optional field.
  • Birthday uses dd-MM-yyyy and cannot be in the future. Edited values follow the same validation rules as add.
  • Older saved digit-only phone numbers with at least 3 digits, and older saved numbers with unmatched brackets, remain usable. An edit without p/ keeps the existing number; a supplied p/ value must follow the current rule.
  • Each non-tag field may be specified only once. Unknown parameters are rejected.
  • t/TAG replaces all existing tags; repeat it to specify several replacement tags. t/ with no value clears the tag set.
  • at/TAG adds a tag without removing other tags, while rt/TAG removes only that tag from the contact. These may be repeated or mixed and are applied in command order. Neither may be mixed with t/.
  • Tag matching ignores case. Adding an existing tag or removing an absent tag has no effect. A valid new tag named by t/ or at/ is saved as a custom tag. Empty at/ and rt/ values are invalid.
  • t/ replacements may contain at most 15 tags, and at/ cannot give a contact more than 15 tags. A contact saved with more than 15 tags can still be edited with at/ and rt/, or without changing its tags, as long as the edit does not increase its number of tags.
  • If the contact's name changes, events they are assigned to show the new name.
  • A new name already used by another contact, ignoring case and extra spaces, is rejected.
  • An edit is saved to the local data file before it appears in the contact list. If the file cannot be read or written, the edit is not applied. A failed write reports Contact could not be saved. No changes were made.; invalid stored data reports Saved data could not be loaded. Check the local data file.
  • On success, edit confirms the updated name, phone, email, and role. The selected contact's details pane shows its current optional fields and tags.

Successful feedback example:

Contact updated successfully:
Name: Aisha Tan
Phone: +6598765432
Email: aisha@example.com
Role: President

The same contact's details pane after edit updates their phone number and email address.

Examples:

  • edit 1 p/91234567 e/johndoe@example.com Edits the phone number and email address of member ID 1 to be 91234567 and johndoe@example.com respectively.
  • edit 2 n/Betsy Crower t/ Edits the name of member ID 2 to be Betsy Crower and clears all existing tags.
  • edit 3 r/Logistics Lead m/Handles venue bookings Updates a role and note.
  • edit 3 b/ a/ o/ m/ Clears the optional birthday, address, organisation, and note.
  • edit target/alice@example.com r/Vice-President Updates a contact even if the current list is filtered.
  • edit 3 at/Sponsor rt/Logistics Adds Sponsor, then removes Logistics without changing other tags.
  • edit 2 lv/30-11-2026 Marks the contact with member ID 2 as on leave until 30 November 2026, and edit 2 lv/ ends their leave.

Edited contact fields use the same validation error messages as add. Empty optional fields (b/, a/, o/, lv/, m/, and t/) clear those values and are accepted. Additional errors are listed below.

Marking a contact as on leave

Records that a contact is temporarily unavailable until a given date, so you do not need to remember to clear it afterwards. Leave is an optional contact field, set with lv/ in add or edit.

Format: edit MEMBER_ID lv/LEAVE_END_DATE or edit target/IDENTIFIER lv/LEAVE_END_DATE

  • LEAVE_END_DATE is the last day of leave, in dd-MM-yyyy format. It must be today or a later date.
  • The contact is on leave up to and including that date. While on leave, their card in the contact list shows On leave until LEAVE_END_DATE, and the details pane shows the date under On leave until. The same leave label appears beside their details in the Events tab when they are assigned to the selected event.
  • From the day after, the contact is no longer shown as on leave. You do not need to run any command: if CoordiMate is open at midnight, the Contacts and Events views update within a minute.
  • The ended leave date stays in the data file but has no effect. The details pane shows — (not on leave).
  • Setting a new date replaces the previous one. edit MEMBER_ID lv/ with no date ends the leave immediately.
  • A contact on leave can still be assigned to events and have attendance marked.

Examples:

  • edit 2 lv/30-11-2026 marks the contact with member ID 2 as on leave until 30 November 2026.
  • edit target/aisha@example.com lv/15-12-2026 changes Aisha's leave to end on 15 December 2026.
  • edit 2 lv/ ends the leave of the contact with member ID 2.

An invalid or repeated lv/ is rejected with the same error messages as edit.

Deleting a contact: delete

Finds a saved contact and asks for confirmation before deleting it.

Formats: delete MEMBER_ID · delete n/NAME · delete p/PHONE · delete e/EMAIL

  • Supply exactly one identifier. MEMBER_ID is the contact's permanent numeric ID and searches all saved contacts, independently of the currently displayed list, including empty search or filter results.
  • Name matching is exact apart from letter case and extra spaces. Phone matching ignores spaces, hyphens, and brackets. Email matching ignores letter case and surrounding spaces. These identifiers search all saved contacts, including those hidden by a search or filter.
  • CoordiMate shows the contact's ID: <number>, name, phone, email, and role, followed by Confirm deletion? [y/N]. Type y or Y to delete; surrounding whitespace is ignored. n, N, Enter, or any other input cancels. A cancelling input is not run as a command; enter it again if that was your intention.
  • A confirmed deletion removes the contact from all event member lists, including past events. The events and other contacts remain saved. A cancelled deletion makes no changes.
  • A confirmed deletion is saved before it appears in the contact list. A corrupt data file or failed write leaves the contact and events unchanged and reports a contact load or save error.

The Confirm deletion? [y/N] prompt shown after delete, before the user responds.

Examples:

  • list followed by delete 2, then y, deletes the contact with member ID 2.
  • If Betsy's member ID is 12, search Betsy followed by delete 12, then Y, deletes Betsy regardless of her position in the results.
  • delete e/aisha@example.com, then y, deletes that saved contact even if a filter hides it.

On confirmation, feedback is Contact deleted successfully: NAME. Missing, invalid, unknown, repeated, and non-matching identifiers are rejected without opening a confirmation prompt.

Condition Error message
The member ID does not exist. No contact exists with member ID: {MEMBER_ID}. Use an existing member ID.
Different prefixed identifiers are combined, or text or a member ID appears before a prefixed identifier. Specify exactly one contact identifier. Example: delete n/Aisha Tan
n/, p/, or e/ is empty or contains only whitespace. Contact identifier must not be empty. with an example matching the prefix used, e.g. Example: n/Aisha Tan

matching contact details with ID: <number>
Use a member ID, phone number, or email address to identify the contact.
The contact changes after the confirmation prompt. Contact ID: {MEMBER_ID} has changed since deletion was requested. Run delete again.

Cancelling reports Deletion cancelled. No changes were made. If saving a confirmed deletion fails, the command reports Contact could not be saved. No changes were made.

Searching contacts: search

Lists contacts whose name, phone number, email, address, or organisation contains the given keyword or phrase.

Format: search KEYWORD

  • Matching is case-insensitive across all five fields; for example, hans matches Hans, and search ipek finds a contact named İpek.
  • Partial words match; for example, Han matches Hans.
  • The entire keyword is matched as one substring within a field. Spaces and word order matter: search Hans Bo matches Hans Bo Yang, but does not match Bo Hans or separate contacts named Hans and Bo.
  • Several spaces in a row count as one, in both the keyword and the saved values. For example, search Kent Ridge matches an address containing Kent Ridge. Addresses are still saved and displayed as entered.
  • Phone numbers are also matched ignoring spaces, hyphens, and brackets, so search 91234567 finds 9123 4567, and search 9123 4567 finds 91234567.
  • Surrounding quotation marks are optional: search "Jurong West" and search Jurong West give the same results.
  • Leading and trailing spaces are ignored. An empty keyword is rejected.
  • Search checks all saved contacts, including those hidden by the current search or filter.
  • Results replace the displayed contact list. Permanent member IDs remain unchanged; edit, delete, assign, and unassign accept those IDs even for hidden contacts. Use list to show everyone.
  • If nothing matches, the displayed list is empty and a no-matches message is shown.

The contact list narrowed down to the one match for search John.

Examples:

  • search John matches John Doe by name and john@example.com by email.
  • search 9123 matches a phone number containing 9123, such as 91234567.
  • search EXAMPLE.COM matches email addresses containing example.com, regardless of case.
  • search jurong west matches addresses containing Jurong West.
  • search student affairs matches organisations containing Student Affairs, such as NUS Student Affairs.

Success: 1 contact(s) found matching "John".

If nothing matches: No contacts found matching "John".

To narrow contacts by an exact tag, event, or organisation instead, use filter.

Filtering contacts: filter

Lists the contacts that have a given tag, are members of a given event, or belong to a given organisation.

Format: filter FIELD/VALUE [FIELD/VALUE]...

  • FIELD is tag, event, or organisation, ignoring case. These are full words, not the prefixes used by other commands; for example, use tag/EXCO, not t/EXCO.
  • VALUE must match a saved value in full, ignoring case. Unlike search, partial values do not match: filter organisation/NUS does not match NUS Student Affairs.
    • tag/VALUE lists contacts that have the tag. The tag must be in the tag list shown in the Tags tab.
    • event/VALUE lists the members of the event with that name.
    • organisation/VALUE lists contacts whose organisation is that value. At least one contact must have it. Several spaces in a row count as one, so organisation/NUS Student Affairs matches NUS Student Affairs.
  • When several filters are given, a contact must match all of them.
  • Filter checks all saved contacts, including those hidden by the current search or filter.
  • Results replace the displayed contact list. Permanent member IDs remain unchanged; edit, delete, assign, and unassign accept those IDs even for hidden contacts. Use list to show everyone.
  • If a value does not exist, the command is rejected and the displayed list stays as it was.
  • An event filter stays up to date while it is shown, like members: contacts assigned with assign appear, contacts removed with unassign disappear, and renaming the event with editevent keeps the filter working. If the event is deleted, the list becomes empty.
  • A tag filter also follows its tag: renaming the tag with edittag keeps showing the same contacts. If the tag is deleted, the list becomes empty.

Quotation marks

  • A value may be wrapped in quotation marks, which are removed: filter event/"Final Concert" and filter event/Final Concert give the same results.
  • Inside quotation marks, text that looks like another field is kept as part of the value: filter event/"Planning tag/review" is one filter for an event named Planning tag/review. Such a name can exist only in a data file edited by hand, because addevent and editevent do not accept it.
  • A quotation mark with no closing quotation mark is kept as part of the value when no field follows it: filter event/"Cali matches an event named "Cali. A filter like this must be the last one in the command, e.g. filter tag/EXCO event/"Cali.
  • A quotation mark with no closing quotation mark, followed by another field, is rejected because it is unclear where the value ends: filter event/"Cali tag/EXCO.

The contact list narrowed down to members matching filter tag/EXCO.

Examples:

  • filter tag/EXCO lists contacts tagged EXCO.
  • filter event/Final Concert lists the members of Final Concert.
  • filter organisation/nus student affairs lists contacts whose organisation is NUS Student Affairs.
  • filter event/"Final Concert" tag/EXCO lists members of Final Concert who are also tagged EXCO.

Success: 2 contact(s) found.

If every value exists but no contact matches all the filters, the displayed list is empty: No contacts match the specified filters.

Condition Error message
No saved tag, event, or organisation has the supplied value. No saved tag, event, or organisation matches that value. Use a value from the saved data.
tag/, event/, or organisation/ has no value, contains only whitespace, or has an empty quoted value. Filter value must not be empty. with an example matching the field used, e.g. Example: tag/Publicity

Archiving contacts: archive, unarchive

Archiving hides a contact or an event from the normal lists without deleting it, so that the lists show only the people and events you are working with now. Everything is kept: an archived contact keeps its details and stays a member of its events, and an archived event keeps its details, members, and attendance records. Use list archived to see archived items, and the unarchive commands to bring them back. Events are archived with archiveevent.

Formats:

  • archive MEMBER_ID archives the contact with that member ID.
  • unarchive MEMBER_ID restores the contact with that member ID.

Both commands work from any view and then open the Contacts tab, so you can see the change. unarchive also selects and reveals the restored contact when it is in the displayed list. MEMBER_ID is the permanent ID shown on each contact, as in edit and delete, so it does not depend on the displayed list. A contact hidden by a search, a filter, or the archived view can still be archived or restored.

While a contact or event is archived:

  • It does not appear in the Contacts or Events tab, or in the results of search, filter, or members. It appears only in the archived view opened by list archived, where an archived contact's card shows an Archived badge.
  • It is marked (archived) wherever it still appears: an archived contact in event member lists and in tag member lists in the Tags tab, and an archived event in the event list of each of its members' details.
  • An archived contact cannot be assigned to an event, but can still be removed from one with unassign.
  • Its name stays taken: add or addevent with the same name is rejected as a duplicate.

A contact's card marked with the Archived badge, shown in the list archived view.

Examples:

  • archive 12 archives the contact with member ID 12.
  • unarchive 12 restores that contact, from either view.

Success: Archived contact: {NAME}. or Unarchived contact: {NAME}. The change is saved immediately and stays after restarting.

Condition Error message
No contact has that member ID. No contact exists with member ID: {MEMBER_ID}. Use an existing member ID.
archive is used on a contact that is already archived. {NAME} is already archived. No changes were made.
unarchive is used on a contact that is not archived. {NAME} is not archived. No changes were made.

If saving fails, the command reports Contact archive status could not be saved. No changes were made. The contact and the existing data file remain unchanged.

Assigning and removing members: assign, unassign

assign adds contacts to an event as members. unassign removes members from an event; the contacts themselves are not deleted.

Formats:

Managing data

Saving the data

Saved member IDs stay tied to the same contacts across restarts. Older files receive unique IDs for contacts that lack them when loaded; the next successful save records those IDs.

IDs are assigned automatically and cannot be changed through commands. Deleting a contact leaves a gap; adding another contact does not reuse the deleted ID. Editing contacts, searching, filtering, and changing list order keep existing IDs. The clear command starts an empty dataset, with IDs starting from 1 again.

CoordiMate automatically saves data after commands that change it. You do not need to save manually.

A command that changes your data is saved to the data file before the change appears in the app. If the data cannot be saved, the command is rejected with an error such as Event could not be saved. No changes were made. and both the app and the data file stay as they were, so what you see always matches what is saved.

Commands that only change the displayed view, such as list, search, and filter, do not save the data file. If another CoordiMate window changes the data file while this window is open, this window can still display its previously loaded data. Its next command that saves data is rejected with The data file changed in another window. Reopen this window before saving. No changes were made. The newer data file is preserved. Close and reopen the stale window before making further changes.

Editing the data file

CoordiMate data is saved automatically as a JSON file [JAR file location]/data/coordimate.json. Advanced users are welcome to update data directly by editing that data file.

If the file becomes invalid: CoordiMate shows a warning at the next launch and leaves the original file unchanged. Select OK to close CoordiMate, repair or restore the file path shown in the warning, then restart the app. When a saved value fails validation, the warning also shows the reason and identifies the contact or event when possible. CoordiMate does not open its normal interface or accept commands until the file can be loaded.

Names:

  • Each name in an event's members list must exactly match the name of a saved contact, or the data file is invalid.
  • Contact and event names are read with several spaces in a row treated as one. If two contacts, or two events, have names that differ only in letter case or spacing (e.g. Alex Yeoh and Alex Yeoh), they are duplicates and the data file is invalid; rename or remove one of them.

Event name migration:

  • Event names containing Unicode space separators, including em and non-breaking spaces, are normalised to ordinary spaces when loaded. At startup, saved events whose names contain whitespace followed by parameter-like text (for example, Planning followed by an em space and c/review) are deleted because those names cannot be used in event commands. This also applies to archived events. A warning lists the deleted names, showing non-ordinary whitespace as codes such as \u2003.
  • If event names were distinct under the older Unicode whitespace rules but now normalise to the same name, all events are kept: later collisions receive an available suffix such as (2). Long names are shortened to fit the suffix within the 100-character limit. The warning lists the old and new names; members, attendance, reminder dismissal history, and archive status are preserved.
  • These migrations are saved before the data is loaded. Other contacts and events are preserved. If the remaining data is invalid or cleanup cannot be saved, the file is left unchanged.

Contact IDs:

  • Each contact's memberId must be a unique integer from 1 to 2147483647. Keep existing IDs unchanged.
  • Keep the top-level nextMemberId field: it must exceed every saved ID, must not be reduced after deleting contacts, and cannot exceed 2147483648.

Archived status: Each contact and event has an archived value of the JSON boolean true or false, without quotes. A missing or null value is read as false; quoted strings such as "false", numbers such as 17, and other values make the data file invalid.

Other field types: Other saved values must also use the correct JSON type. For example, a phone number must be a quoted string, even when it contains only digits; event attendance values must be strings. Numbers or booleans in text fields, and quoted booleans in boolean fields, make the file invalid. The warning identifies the affected field when possible.

Tags:

  • If a contact uses a tag that is missing from the top-level tags list, CoordiMate adds it to the global tag list when the file is loaded. Existing top-level tags, including unused tags, retain their saved order and capitalization.
  • A contact saved with more than 15 tags still loads with all of its tags, but commands cannot give it more tags.

Certain edits can cause CoordiMate to behave in unexpected ways, for example if a value entered is outside the acceptable range. Edit the data file only if you are confident that you can update it correctly.

If preferences.json contains invalid JSON or a value of the wrong type, CoordiMate warns you and uses default preferences for that session when the data file is valid. For example, windowMaximized must be true or false without quotes, and window width and height must be JSON numbers. A missing or null hasSeenTutorial, windowWidth, windowHeight, or windowMaximized uses its default value (false, 1200, 850, or true, respectively). Other values of the wrong type still make the file invalid. The original preferences file is kept unchanged, including when you close the app. Repair or restore the file shown in the warning before the next launch. If both the data and preferences files are invalid, one recovery warning lists both problems and file paths, then CoordiMate closes after OK.

FAQ

Q: How do I transfer my data to another computer?
A: Install the app on the other computer and overwrite the data file it creates with the data file from your previous CoordiMate home folder.

Known issues
